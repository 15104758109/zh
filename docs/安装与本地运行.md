# 安装与本地运行

本说明只覆盖本地环境和操作方式。产品定位与业务范围见 [README](../README.md) 和
[V7 设计文档](v7设计文档_20260709_终版.md)。

## 前置条件

- Node.js 24
- pnpm 9
- Docker Desktop，且已有 `n8n-pgvector`、n8n 与 PostgREST 本地运行时
- 工作区根目录的 `.env`，用于本地 secret、n8n credential resolution 和明确测试变量

本项目不新建容器，不需要 MySQL、SQLite、SQL Server 或云部署。`.env` 不提交，
也不能将凭据写入页面、workflow 附件或源码。

## 安装依赖

```powershell
pnpm install --frozen-lockfile
```

## 启动 Web

```powershell
pnpm start
```

默认监听 `http://127.0.0.1:4176`，入口为
`http://127.0.0.1:4176/workbench`。使用其他端口：

```powershell
$env:PORT=4191
pnpm start
```

`pnpm start` 只启动 Web。它不会启动、停止或重建 PostgreSQL、n8n 或业务数据。
在进入需要真实后端的页面前，确认现有本地运行时可用：

```powershell
docker ps --format "table {{.Names}}\t{{.Status}}"
```

## 可选 FP008-02 服务

仅在需要独立推演引擎时启动：

```powershell
pnpm --filter @zhreplan/api start:fp008
```

Web 通过 `FP008_SERVICE_URL` 读取该服务地址；未设置时使用本地默认地址。

## 验证

```powershell
pnpm typecheck
pnpm build
pnpm test:db
pnpm test:business
pnpm test:pages
pnpm test:web
```

- `test:db` 使用 canonical SQL 创建隔离临时库并验证 B1-B8 数据旅程。
- `test:business` 验证页面、n8n 与 RPC 的业务职责。
- `test:pages` 验证页面适配、状态、workflow mapping 与 FP008 服务。
- `test:web` 验证正式路由、原型移植与本地静态资源。

最终验收必须使用真实本地路由，检查视觉、正常/空/加载/失败/恢复状态、直接刷新、
跨页作品上下文、控制台错误和真实按钮。静态测试不能替代页面到 PostgreSQL 的真实旅程。

## 数据与文件安全

`pnpm db:v7:rebuild` 只用于有意清空的本地产品库重建，不能作为已有业务数据的
增量迁移命令。修改 live n8n 或数据库前保留即时回滚备份，发布后必须读回并通过
真实页面验证。

根目录 `.tmp-*` 已被 Git 忽略，用于临时执行数据、日志或回滚材料。需要长期保存
的 dump/SQL 应移到仓库外、按日期归档；确认没有回滚或审计用途后才删除。
