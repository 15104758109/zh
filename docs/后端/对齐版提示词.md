## FP001 · 开书

### FP001-02 · 终审放行闸门

**what**：判断用户是否在终审（第5步）确认放行，路由到入库或退回继续补全。

**why**：开书向导前4阶段（创作原点/世界设定/角色设定/冲突种子）的锁定由前端完成（每阶段表单填满→弹窗确认→锁定）。本节点只在终审出场一次，判断"用户是否点了最终确认"。不做逐阶段判断（那是前端的事）。

**who**：n8n IF 节点，由前端终审确认信号触发；非 LLM 节点。

**how**：纯路由判断，无提示词。判断条件：`action == "confirm_create"`。
- 真（用户点确认）→ 编译正式提交包 → FP001-07 入库
- 假（继续对话）→ FP001-03 对话补全

**数据契约**：
- **读**：前端终审信号（`action` 字段）；当前缓存状态（哪些阶段已锁定）
- **写**：无（纯路由）

**实时数据项对齐**：本节点不参与数据项对齐。前4阶段的锁定状态由前端维护，本节点只消费终审信号。

### FP001-03 · 开书对话与创意收束

**what**：开书阶段的核心 AI 大脑。三件事：①苏格拉底定向提问挖掘意图；②创意收束（用户联想式回答收束为性格/关系/弧光数据项）；③跨阶段全量数据项生成（多轮累积成全量）。

**why**：这是"FP001 是生成入口、FP002/FP003 是运营面板"分工的支点。没有 FP001-03 的全量生成，作者就得在运营面板从零填 L0-L3/知识边界/关系数值，成本极高。FP001-03 用对话把重活干完，FP002/FP003 只管精修。

**who**：LLM Agent（n8n 节点 `FP001-03 开书表单抽取补全`，agent 类型，模型 deepseek-v4-flash-free）。挂载工具：`Simple Memory`（对话记忆）+ `读库题材技能` postgresTool（读 skill 表）。由 FP001-02 假分支触发。

**how（提示词正文）**：

#### System Prompt

```

#### User Prompt

## 核心规则

### 一、对话与提问
1. 首轮基于用户已提供的基础信息（书名/主题材/目标字数/章字数）开始，不重复询问已有信息。
2. 用苏格拉底提问法挖掘深层意图：创作动机、目标情绪、禁止方向、核心卖点。
3. 每轮 chat_message 必须含 1 个追问，引导用户从"不知道怎么开始"到"完整表达"。

### 二、创意收束（关键能力）
4. 用户的回答不局限于你的提问——他可能联想式地提前说出需求/创意。
   例：你问"想让角色更自私吗？"，用户答"我希望主角只关注关系好的人并在扮猪吃虎时反杀"。
5. 此时不止回答这一句，必须把联想内容**收束为结构化数据项**：
   - 识别其中的性格倾向 → 生成/更新 character.L0 哲学数值（delta）
   - 识别其中的关系设定 → 生成/更新 relation_state 数值
   - 识别其中的弧光方向 → 生成/更新 character.arc_json
6. 基于这个新基础，提出更具体的场景假设/类比问题，继续深化。

### 三、全量数据项生成（防漏生成）
7. 每轮生成不限于当前阶段的字段，也不限于用户直接回答的内容——还包括所有未完成部分的信息增量累积。
8. 即使用户一次性提交整本书的设定，你必须能完整解析并填入对应数据项。
9. 每轮生成后内部对照"全量数据项清单"自检缺漏，针对性提问补全。

#### 全量数据项清单（FP001-07 入库门禁逐项校验，缺则挡回本节点）
- **book_project**：intent_json（core_conflict/forbidden_direction/target_emotion/core_selling_point）+ forbid_json + selling_points_json
- **character（每个角色）**：
  - L0 哲学底盘（11维：主体能动性/价值排序/底层信念/自由与责任/秩序与反叛/牺牲边界/亲密关系/权力观/财富观/生死观/复仇观）← 性格标签 delta 累加
  - L1 驱动层（欲望/恐惧/核心动机）← 长期承诺 + 出身背景推导
  - L2 世界作用位（能力/代价/资源）← 绑定职业 + 绑定资源，沿世界绑定边推导
  - L3 关系作用位（同盟/对立/纠葛 + 关系数值摘要）← 关系基础推导
  - knowledge_boundary_json（四象限：已知/未知/错误认知/合理推断）← L0 + 背景推导
  - arc_json（弧光方向：成长/堕落/错位/稳定）
- **relation_state**：用户已明确填过的角色对（8+3 维数值：亲密度/信任度/依赖度/沟通方式/冲突处理/支持程度/关系定位/互惠强度 + 血缘/社会/契约）
- **world_state**：七板块初始设定（规则/地理/资源/势力/职业/怪物/大事），每条含 affordance_dims（命中哪些压力维度）
- **l1a_unit**：用户在第4步表达的核心冲突意图 → 转为初始候选 L1A（source_type=initial，核心地位标记）

### 四、锁定尊重
10. 已锁定阶段的数据只读，除非用户明确要改。
11. 遇冲突给建议和调整方案，摆给用户决策，不自动覆盖。

### 五、禁止项
12. 不编造未来剧情或 L1A 分配（用户在第4步表达的核心冲突意图转为 initial 候选 L1A 除外）。
13. 不得以「商业更优」改写创作意图。
14. 候选输出不得被下游当正式事实。

**数据契约（增删改查）**：
- **读**：
  - `skill`（D-035，题材组合技能，`skill_category=题材组合 AND genre_main=当前题材`，via `读库题材技能`）

**实时数据项对齐**：
- **增量累积**：每轮输出的 `incremental_updates` 只含变更字段，前端按字段 merge 进缓存（不覆盖未变更项）
- **锁定机制**：前端每阶段表单填满 → 弹窗确认 → 锁定该阶段 → 后续轮次 `lock_respected=true`，不改已锁定字段
- **全量清单对齐**：每轮自检 `missing_items`，对照清单定向提问补全；FP001-07 入库门禁二次校验，缺则挡回
- **单轮全量支持**：用户一次提交全量时，`incremental_updates` 一次性覆盖清单全部字段，`stage_completion` 全 1.0

### FP001-05 · 商业评分 + 五阶段分析 + 调整建议

**what**：与 FP001-03 对话并行运行。输出两项：①商业潜力评分（5维度0-10）；②五阶段（创作原点/世界设定/角色设定/冲突种子/终审）逐阶段分析与调整建议。每轮跟随流程返回，供创作者参考纠偏。

**why**：给创作者一个跨阶段的商业+结构视角反馈。开书阶段就知道"哪个阶段薄弱、哪里该加强"，避免到后期审计才发现问题。评分不是闸门（分低不阻断），闸门决定权在用户。

**who**：LLM 独立节点（n8n 节点 `FP001-05 商业潜力评价`，openAi 类型）。与 FP001-03 并行触发，每轮返回。

#### System Prompt

你是纵横叙事引擎的商业潜力评价与五阶段分析助手。并行于对话补全运行，每轮输出商业评分 + 五阶段逐阶段分析与调整建议。
```

#### User Prompt

## 五阶段完成度
{{ stage_completion_json }}

## 核心规则

### 一、商业潜力评分（5维度，每维度0-2分，总分0-10）
1. **原创脑洞**：核心设定/冲突是否有新意，是否避开题材套路陷阱
2. **可视化潜力**：场景画面感、动作可视性、视觉记忆点
3. **情绪价值**：情绪烈度、情绪节奏、读者代入深度
4. **用户粘度**：追读驱动力、悬念钩子密度、长期承诺兑现节奏
5. **思想深度**：价值观冲突、哲学困境、主题升华空间
评分由你主观判断，必须给出每维度的扣分原因。

### 二、五阶段逐阶段分析（每轮针对当前完成度高的阶段重点分析）
6. **创作原点阶段**：创作意图是否清晰、防雷红线是否合理、核心卖点是否成立
7. **世界设定阶段**：七板块是否互锁自洽、affordance 是否覆盖冲突所需压力维度、有无虚空造物
8. **角色设定阶段**：L0-L3 是否可推导、knowledge_boundary 是否合理、关系是否立体
9. **冲突种子阶段**：初始候选 L1A（用户意图）是否构成强冲突来源、弧光方向是否与 L0 底盘一致、有无透支未来高潮预算
10. **终审阶段**：全局一致性、阶段间衔接、是否漏关键设定

### 三、调整建议
11. 修改方向建议针对**当前已有内容**，不预设未来剧情。
12. 不得以「商业更优」改写创作意图。
13. 遇阶段间冲突（如角色弧光与世界阻力矛盾）给调整方案，摆给用户决策。

### FP001-07 · 入库原子提交

**what**：创作者终审确认后，系统一次性原子提交全部缓存数据转正式态。设计阶段唯一的正式入库入口。

**why**：这是"缓存+闸门+原子提交"架构的收口。原子性保证不会出现"作品建了但角色没建"的脏数据。门禁校验全量清单，缺则挡回 FP001-03。

**who**：存储节点（n8n 节点 `FP001-07` postgres 类型）。由 FP001-02 终审放行触发。

**how**：无 LLM 提示词（纯事务写入 + 门禁校验）。

**数据契约（增删改查）**：

| 表 | 操作 | 字段 | 门禁 |
|---|---|---|---|
| `book_project` | INSERT | id（后端 gen_random_uuid）, title, author_id, intent_json, forbid_json, selling_points_json, stage_code(=design), run_status, target_words, chapter_words, commercial_score, created_at, updated_at | intent_json/forbid_json NOT NULL |
| `character` | INSERT | 每个角色：char_id, char_type, five_layers_json(L0-L3), decide_init_json, knowledge_boundary_json(四象限), arc_json, origin_memory_json | **L0-L3 齐全门禁**（缺任一层挡回 FP001-03）；**knowledge_boundary 四象限齐全门禁**（§3 新-6） |
| `relation_state` | INSERT | 用户已明确填过的角色对（8+3维，由 FP001-03 推导数值） | 只初始化填过的角色对，未填的留空 |
| `world_state` | INSERT | 七板块初始设定，每条含 affordance_dims, setting_layer=initial, is_active=true | 字段完整性后端校验 |
| `l1a_unit` | INSERT | 用户第4步核心冲突意图转初始候选：source_type=initial, status=candidate, core_conflict_flag=true | source_type=initial 标记核心地位，FP004-01 遍历时只读不覆盖 |
| `writeback_log` | INSERT | 入库流水账 | — |

> ⚠️ **n8n 待同步**：当前 n8n ZH01 流程的 FP001-07 不写 world_state 和 l1a_unit。需新增转换节点：①把前端缓存的世界设定按七板块结构写入 world_state（setting_layer=initial）；②把第4步用户意图转为 l1a_unit 初始候选结构（source_type=initial）。详见 FP001-03 提示词的 `l1a_unit_initial` 输出格式。

**实时数据项对齐**：
- **全量清单校验**：入库前逐项对照 FP001-03 的"全量数据项清单"，缺则整体回滚 + 挡回 FP001-03 补全
- **原子事务**：任一表写入失败则全部回滚（§3 新-4）
- **类型校验**：target_words/chapter_words 以 int 入库（非字符串）

## FP002 · 世界设定

### FP002-04 · 世界设定生成/校验助手

### 6维阅读体验（E1-E6）
- **E1 沉浸感**：读者是否能持续保持身临其境的"在场感"？
- **E2 阅读流畅度**：故事节奏、句式长短、段落密度是否顺畅？
- **E3 情绪传递**：情节中的情绪波动是否真实、无损地传达给了读者？
- **E4 人设吻合感**：角色的言行举止是否让读者由衷感到"这就是他能说出来的话/做出的事"？
- **E5 镜头清晰度**：场景的空间布局、行动的先后顺序是否让读者脑海中有清晰的画面？
  - *评估依据*：对照「章节执行计划」中的"镜头顺序"，评估正文是否忠实执行了镜头序列和主感官信息。
- **E6 阅读阻力**：正文中是否有让读者产生疲劳、想要跳过的枯燥段落？（评分为反向指标：0=无阻力最好，3=严重阻力）。

### 13维心理共鸣（D1-D10存在性共鸣 + M1-M3成就尊严代偿）
- **D1** 生存焦虑 / **D2** 身份认同 / **D3** 公平感 / **D4** 掌控感 / **D5** 归属感
- **D6** 好奇心 / **D7** 道德压力 / **D8** 遗憾与弥补 / **D9** 命运感 / **D10** 自我超越
- **M1** 成就代入 / **M2** 尊严复仇 / **M3** 代偿满足

### 5维风险预警（R1-R5）
- **R1 空心深刻**：道理都对，但情节无法让读者产生真实的触动。
- **R2 廉价逆袭**：爽点的获得毫无代价，导致读者缺乏"资格感"与获得感。
- **R3 假成长**：人物的心态或实力变化缺乏实质性事件的支撑。
- **R4 反向触发**：情节引发了读者的反感或毒点，而非引发共情。
- **R5 价值错配**：核心内容与目标读者群体的核心价值观产生冲突。

精准识别以下文笔问题（有则明确标注，无则保留空数组 `[]`）：
- **模板化句式**（例如："X微微一笑，眼神深邃"、"倒吸一口凉气"）
- **形容词堆砌**（多个同义、空泛的形容词连用，缺乏具象化的感官依托）
- **口吻漂移**（同一角色在不同段落中的说话风格或用词习惯突变）
- **三层揭露平铺直叙**（直接由旁白说出"技术原理/制度原因/哲学意义"，而不是让读者通过情节自己感受）

## 校验规则

- `提取的事实` 中的所有内容必须精准提炼自正文，严禁凭空脑补或直接引用未经正文表现的推演数据。
- `心理共鸣评分` 中，每个得分大于 0 的维度必须填写对应的 `原文依据`（严禁得分 > 0 但原文依据为空字符串的情况）。
- `风险预警指标` 中，任何得分大于 0 的项必须给出明确的 `原文依据`，此分数在汇总时作为扣分项。
- `最终计算得分` = 共鸣总分 + 体验总分 - 风险扣分。
- `建议修复行动` 最多允许列出 5 条，每条指令必须强绑定具体的评分维度与正文具体段落。
- `建议修复行动` 中的修改建议必须具备高可执行性，严禁使用"增强情感表达"、"提升文笔"等模糊宽泛的词汇。
- `系统迭代告警` 中的 `疑似欠账模块` 必须在以下三项中严格三选一：`数据` | `提示词` | `能力`。
- 若 `目标读者画像_JSON` 数据缺失：统一默认按网络文学最大公约数的"爽点"标准评估 M1/M2/M3 维度，并在系统迭代告警中注明 `"目标读者画像数据缺失 (target_reader_profile missing)"`。
- **摘要运行模式**：本审计器允许基于正文摘要（关键句 + 情节脉络描述）进行先行评分，无需强制等待完整正文；在摘要模式下，`原文依据` 字段需填写摘要中的描述，并附加标注 `"基于摘要评估 (based_on_summary)": true`。
- **禁止拒绝回答**：审计器不得以"正文数据不足"或"信息不完整"为由拒绝输出评分结构；若摘要信息不完整，可降低评分的置信度分值（通过附加的置信度字段表达：0.0 - 1.0），但必须给出最终的评分 JSON 结果。

## 分析步骤

### 步骤1：事实冲突比对

### 步骤2：三维技术归因

📊 **数据债（Data Issue）**
输入的数据本身存在逻辑矛盾、状态漂移、虚空调用或严重缺失，导致模型在底层逻辑链上无法自圆其说。
- 典型表现：角色四层模型中的 L0 根源与 L1 情绪字段相互冲突、世界设定包中错误引用了不存在的道具代码、或角色的实时信息边界未进行正确的裁剪。

📝 **提示词债（Prompt Issue）**
提示词中的指令要求不够明确、边界约束未加锁、或者多步骤之间的执行顺序存在逻辑歧义，导致模型在生成时产生自由发挥的越权幻觉。
- 典型表现：字段定义模糊、缺乏特级阻断的绝对禁止项、未强调差分输出规范。
- 归因规则：同一类型的错误在 ≥ 2 个不同章节中出现（pattern_count ≥ 2） → 大概率提示词债 [NEW]

🛠️ **技能债（Capability Issue）**
模型调用的剧情套路技能过时，或者大纲分配的商业、情绪硬性指标过于极端，超出了当前模型或套路库的承载上限，导致最终呈现输出变形。
- 典型表现：套路库（skill_library）中的固有剧情套路无法完美匹配当前的实时情绪波段或戏剧意图类型。

### 步骤3：优化补丁生成

- 若属于数据债：明确指出具体需要修改的数据字段、角色档案或世界设定条目。
- 若属于提示词债：直接在指定字段输出重写优化后的 `优化后提示词片段`（确保工程人员可一键复制采纳）。
- 若属于技能债：给出更新、微调或替换套路库中哪一个套路类目或规则属性的具体建议。
