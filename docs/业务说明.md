# 业务说明

## 产品目标

纵横叙事引擎 V7 是本地运行的小说生产系统。创作者从真实页面建立作品、完成
世界设定、角色设定和 L1A 剧情段，随后在同一作品与操作者上下文中完成章节
推演、正文呈现、审计和正式写入。

MVP 的验收不是静态正文或数据库造数，而是同一本书连续经过页面、n8n、RPC、
PostgreSQL 与刷新恢复的真实用户旅程。当前已验证的结果见
[MVP 当前进度](MVP_PROGRESS.md)。

## 业务权威

以下来源按优先级定义产品业务范围：

1. [V7 设计文档](v7设计文档_20260709_终版.md)：业务行为、FP 归属、数据状态与持久化职责。
2. `docs/前端原型_v2/`：页面内容、DOM、CSS、布局和交互；WORLD 使用
   `pages/world-settings-drag-binding.html`。
3. `docs/后端/n8n/*.json`：现有 workflow 的可编辑基线。
4. `docs/后端/对齐版提示词.md`：V7 模型行为实现材料，不扩张业务范围。
5. `db/install/v7-data-rpc-contract.sql`：PostgreSQL canonical 数据与 RPC 合同。

源码、数据库现状和测试只能证明当前实现，不能替代 V7 的业务定义。文档外的
用户可见字段、默认值、阈值、状态、RPC 或工作流职责，需要先按业务影响获得批准。

## 用户旅程

```text
作品输入 -> 世界/角色/L1A 设计 -> L1A 锁定
-> 章节推演 -> 候选正文与审计 -> 主编裁决 -> 正式章节 -> 刷新恢复
```

一个功能交付以 V7 FP 为单位：

`用户动作 -> 页面收集意图 -> n8n workflow -> RPC/state -> PostgreSQL -> 页面结果`

页面只展示 scoped projection、收集用户意图、发送请求和呈现 loading/error/result。
它不直连 PostgreSQL、不推断服务端状态，也不伪造成功结果。

## 技术职责

- 浏览器页面：保留原型 DOM/CSS/交互，在原位绑定真实数据、加载、错误和刷新恢复。
- n8n：执行 V7 分配的业务工作流、模型调用、RPC 编排与状态流转。
- PostgreSQL：唯一数据库方言，负责 canonical 数据、RPC 与持久化合同。
- FP008-02：唯一高代码例外，使用 Node.js/TypeScript 推演引擎。

项目使用 Node.js、pnpm、PostgreSQL 和现有 n8n 运行时；不新建第二前端框架、
路由器、数据库方言或编排层。

## 质量与边界

测试按成本递增：确定性 DTO/RPC、最小合法 workflow 输入、相邻合同、真实
页面旅程与刷新恢复。业务审计 P0/P1 与工程 P0 需分开判断；只有阻断必经链路、
造成错误持久化或虚假成功的问题才是工程 P0。

模型、书稿、设定和角色输出只属于当前 book scope，不进入共享默认值、通用
workflow 规则或跨书测试。协作、审批与后端回滚要求见仓库根目录 [AGENTS.md](../AGENTS.md)。
